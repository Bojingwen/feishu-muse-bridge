# feishu-muse-bridge

[简体中文](README.md) | [English](README.en.md) | 日本語

**Muse（Meta のパーソナル AI アシスタント）本人**を Feishu（Lark）に接続します。Feishu のグループでボットを @ するか、直接 DM を送るだけで、あなた自身の Muse と会話できます。チェーンの中に**サードパーティの大規模言語モデルは一切ありません**——返信はすべて、記憶とツールを持つ Muse 本人が書きます。

> このリポジトリは Muse のスキルパッケージでもあります。リポジトリの URL をあなたの Muse に渡せば、`SKILL.md` の手順に従って自分でブリッジをデプロイできます。

## アーキテクチャ

```
Feishu グループ / DM --(グループでは @ボット、DM は直通)--> feishubridge デーモン
  (Go, Feishu 長接続 WebSocket —— 公開 IP / コールバック URL 不要)
  --> bridge-data/inbox/<message_id>.json   (同時にチャットへ
                                             「Muse が考え中…」のプレースホルダーを投稿)
  --> Muse の hook が 10 秒ごとに受信箱をポーリングし、Muse 本人を起こす
  --> Muse がメッセージと履歴を読み、返信（と添付ファイル）を
      bridge-data/outbox/ に書き出す
  --> デーモンがプレースホルダーを完全な返信に置き換え、
      添付ファイル（画像 / 動画 / ファイル）を送信する
```

返信には数十秒かかり（ポーリング＋思考時間）、プレースホルダーが答えに置き換わる形でメッセージ全体が届きます。トークン単位のストリーミングではありません。

## 特長

- **サードパーティモデルなし**：チェーンにあるのは Feishu、ローカルブリッジ、Muse 本人だけ
- **公開エンドポイント不要**：Feishu の長接続モードなので、ドメイン、公開 IP、トンネリングは不要
- **グループは @ のときだけ返信、DM は直接返信**；mentions 配列のないプレーンテキストの `@ボット名` も認識
- **添付ファイル送信**：画像、動画、ファイルに対応。動画は自動で faststart に再多重化し、最初のフレームをカバー画像にします（これがないと一部の Feishu クライアントで再生不可と表示されます）
- **ループ防止**：ボットが自分のメッセージに反応することはありません
- **プレースホルダーの永続化**：デーモンを再起動しても「考え中…」のプレースホルダーは正しく返信に置き換わります
- **自己修復ウォッチドッグ**：起動用 hook が 10 秒ごとのポーリングのついでにブリッジの管理チェーン全体をチェックします——マシン交換で消えた systemd ユニットは自動で再インストール、停止したサービスは自動起動、死んだままの接続は自動再起動。修復後はユーザーに一行だけ報告します

## Feishu 側の設定

ブリッジが動く前に、Feishu オープンプラットフォームでアプリを設定してください。以下の手順はすべて必須です。

1. **アプリを作成**：[Feishu オープンプラットフォーム](https://open.feishu.cn)にログインし、「開発者コンソール → 企業自社開発アプリを作成」から、名前とアイコンを設定して作成します。
2. **ボット機能を有効化**：「アプリ機能の追加」で「ボット」を有効にします。
3. **認証情報を取得**：「認証情報と基本情報」にある **App ID** と **App Secret** を確認します。デプロイ時にこの 2 つをブリッジの `config/bridge.json` に書き込みます（ローカルにのみ保存し、誰にも送らず、どのリポジトリにもコミットしないでください）。
4. **権限を付与**（「権限管理」で 1 つずつ追加）：
   - `im:message` —— メッセージの送受信（中核となる権限。これがないと何も届きません）
   - `im:message.p2p_msg:readonly` —— DM メッセージの受信（これがないと「グループは動くのに DM は無反応」になります）
   - `im:resource` —— 画像、動画、ファイルの送信
5. **イベント購読を設定**（「イベント購読」ページ）：
   - 受信方式は **「長接続でイベントを受信」** を選択（これにより公開 IP とコールバック URL が不要になります）
   - イベントを追加：**メッセージ受信 `im.message.receive_v1`**
6. **バージョンを公開**：「バージョン管理と公開」で新しいバージョンを作成して公開します。**権限とイベントの変更は公開するまで有効になりません**——「ボットが反応しない」原因で最も多いのがこれで、その後の設定変更のたびに再公開が必要です。
7. **ボットをグループに追加**：対象グループの「設定 → グループボット」でこのボットを追加します。グループでは **@ボット** のメッセージにのみ返信し、DM ではそのままメッセージを送るだけです。

## ローカルへのデプロイ

Feishu 側の準備ができたら、このリポジトリの URL をあなたの Muse に渡し、[`SKILL.md`](SKILL.md) の手順に従ってデプロイさせてください（ブリッジのビルド、設定の書き込み、起動用 hook のインストール、systemd サービスのインストール）。あなたが用意するのは App ID / App Secret と、最後のテストメッセージ 1 件だけです。

## 既知の制限

Feishu の長接続はプッシュ方式です。**クライアントがオフラインの間のイベントはキューに残らず、再配信もされません**。これは Feishu の仕様であり、ブリッジでは変えられません——ウォッチドッグにできるのは、復旧を数秒まで圧縮し、ほとんどの障害に気づく前に自己修復させることです。

## セキュリティについて

このリポジトリには**認証情報、チャット履歴、個人情報は一切含まれていません**。設定テンプレートにはプレースホルダーしかありません。デプロイ時は、あなた自身の App Secret をローカルの `config/bridge.json`（パーミッション 600）にだけ書き込み、決してリポジトリにコミットしないでください。
